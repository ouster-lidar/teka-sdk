# App runtime contract

- Teka owns firewall rules and resource allocations. Rust apps acquire their desired TCP/UDP leases through fallible `sync_tcp_ports` / `sync_udp_ports` before reporting readiness. Run these blocking helpers outside Tokio or in `spawn_blocking`.
- Generic native packet policy uses fallible `sync_nftables` with holder-local `NftablesLease` and `NftablesSet` declarations; only accepted requests enter the replay cache. Initial acquisition failure releases the activated runtime before returning an error.
- The SDK keeps registration and reconnect inside the runtime client. A disconnected or unreachable control plane never releases resources; reconnect reactivates and replays accepted nftables leases before ports. Failed packet-policy replay blocks port replay and retries the current accepted cache.
- Apps requiring nftables enforcement subscribe to `resource_availability()` before readiness. `Unavailable(error)` reports registration loss or failed recovery without assuming kernel state is absent; these apps pause dependent work until `Available` after complete replay and registration, or exit if they cannot pause. Final release publishes `Stopping`. This watch channel retains current availability; rapid transitions may coalesce.
- Final shutdown stops reactivation and serializes release after in-flight control requests. Macro `release` / `release_async` use this final path; ordinary release remains internal for recovery.
- `app-runtime-process APP_ID tcp|udp PORT[-PORT] COMMAND [ARG...]` acquires the inclusive port range before spawning the child and notifying systemd. Readiness means successful acquisition, registration, and process startup; application listeners and health remain with the child. Registration loss stops the child process group and exits nonzero so systemd can restart it.
- Process activation sends `{}` without an HTTP listener hint. The manifest must use `backend.mode = none` or a fixed proxy upstream with `runtime_listen = false`; the host must allocate no HTTP slot for either case.
- Install SIGINT/SIGTERM handlers before activation and run final release on activation, acquisition, spawn, and shutdown paths. Forward the received signal to the child process group, preserve its numeric exit code or actual terminating signal, and kill remaining descendants when its leader exits.
- Complete stageable manifests and the host's generation-aware app watchdog provide crash reclamation; host stop and removal also release resources. Validate native firewall cleanup in the host VM, separately from SDK lifecycle tests.
- Manifest-owned fixed port acquisition is a coordinated host/SDK follow-up. A one-shot startup request cannot replace reconnect lease replay.
